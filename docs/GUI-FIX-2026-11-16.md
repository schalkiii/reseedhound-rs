## 1. 修复的 11 个 GPUI 0.2 API 适配错误

| 错误 | 原因 | 修复 |
|---|---|---|
| 8× E0308 | `rgb()` 返回 `Rgba`，card 闭包参数误声明为 `Hsla` | 闭包参数改 `Rgba`（`text_color` 接受 `impl Into<Hsla>`，自动转换） |

## 2. 结构性重构（main.rs + scheduler.rs）

### 2.1 调度器统一管理手动触发（消除双任务拆借）

原设计：main.rs 里 `tokio::spawn` 一个任务长期借用 `&scheduler` 消费 trigger 通道，与 `scheduler.run()`（`&mut self`）冲突（E0502/E0597）。

新设计（scheduler.rs）：
- `ReseedScheduler` 新增字段 `trigger: Option<mpsc::Receiver<()>>` 和 `on_report: Option<CycleReportCallback>`
- 新增 builder 方法 `with_trigger()` / `with_on_report()`、辅助方法 `take_trigger()` / `report_to()` / `scheduler_enabled()`
- `run()` 主循环改为 **三路 select**：定时间隔 / 手动触发 / 退出信号
- 禁用定时调度时：main.rs 常驻循环内自消费 trigger 通道，手动辅种仍可用（修复了原先"禁用调度→托盘立即辅种失效"的逻辑缺口）
- 新增类型别名 `pub type CycleReportCallback = Arc<dyn Fn(&CycleReport) + Send + Sync>`（顺带消除 clippy type_complexity 警告）

### 2.2 GUI 刷新与退出

- 主线程刷新循环：`tokio::time::sleep` → GPUI 原生 `cx.background_executor().timer(500ms)`；App 退出时 `cx.update()` 返回 `Err` → 循环自然结束
- 退出路径：`cx.on_app_quit()`（注意 GPUI 0.2 该回调要求返回 `Future<Output=()>`，闭包尾部 `async move {}`）→ 发送 stop 信号 + TrayCommand::Quit
